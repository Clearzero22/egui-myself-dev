## 🎯 完整开发流程

### 第一阶段：问题发现与分析

#### 1.1 问题现象

```rust
// 运行默认示例
cargo run -p egui_demo_app --features wayland --release

// 在文本框中输入中文
"你好世界" → 显示为 "◻◻◻◻"
```

#### 1.2 初步分析

**假设**: 可能是字体问题

**验证步骤**:
```bash
# 1. 检查系统字体
fc-list :lang=zh | head -5
# ✅ 系统有中文字体

# 2. 检查 egui 默认字体
ls crates/epaint_default_fonts/src/fonts/
# ❌ 只有 Hack, Ubuntu, NotoEmoji，没有中文字体
```

#### 1.3 根因确认

通过源码分析确认：

```rust
// crates/epaint_default_fonts/src/lib.rs
pub const HACK_REGULAR: &[u8] = include_bytes!("../fonts/Hack-Regular.ttf");
pub const UBUNTU_LIGHT: &[u8] = include_bytes!("../fonts/Ubuntu-Light.ttf");
pub const NOTO_EMOJI_REGULAR: &[u8] = include_bytes!("../fonts/NotoEmoji-Regular.ttf");
// 都不包含 CJK 字符
```

**结论**: 中文显示为方块的直接原因是默认字体不包含 CJK 字符

### 第二阶段：基础解决方案

#### 2.1 字体选择

**考虑因素**:
- 文件大小
- 授权方式
- 字符覆盖范围
- 渲染质量

**最终选择**: Noto Sans CJK
- ✅ 完整 CJK 支持
- ✅ OFL 开源授权
- ⚠️ 文件较大 (~19MB)

#### 2.2 实现方案

**方案 A: 编译时嵌入**
```rust
egui::FontData::from_static(include_bytes!("fonts/NotoSansCJK.ttc"))
// ✅ 简单
// ✅ 无运行时依赖
// ❌ 增加二进制大小
```

**方案 B: 运行时加载**
```rust
let font_bytes = std::fs::read("fonts/NotoSansCJK.ttc")?;
egui::FontData::from_owned(font_bytes)
// ✅ 灵活
// ✅ 可动态切换
// ❌ 需要文件分发
```

**选择**: 方案 A（编译时嵌入）

#### 2.3 代码实现

```rust
fn setup_chinese_fonts(ctx: &egui::Context) {
    let mut fonts = egui::FontDefinitions::default();

    // 1. 加载字体数据
    fonts.font_data.insert(
        "NotoSansCJK".to_owned(),
        egui::FontData::from_static(include_bytes!("fonts/NotoSansCJK.ttc")).into(),
    );

    // 2. 设置优先级
    fonts.families
        .get_mut(&egui::FontFamily::Proportional)
        .unwrap()
        .insert(0, "NotoSansCJK".to_owned());

    // 3. 应用配置
    ctx.set_fonts(fonts);
}
```

**关键点**: `insert(0, ...)` 确保中文字体优先级最高

### 第四阶段：深入研究

#### 4.1 双击事件机制研究

**问题**: 双击是如何检测的？

**研究发现**:
```
用户双击 → winit 收集事件 → egui 计算点击计数
→ 创建 Click 对象 (count=2) → Response::double_clicked() 返回 true
```

**关键源码**:
```rust
// crates/egui/src/input_state/mod.rs
pub(crate) struct Click {
    pub pos: Pos2,
    pub count: u32,  // 1=单击, 2=双击, 3=三击
    pub modifiers: Modifiers,
}

pub fn is_double(&self) -> bool {
    self.count == 2
}
```

#### 4.2 系统标题栏原理

**问题**: 为什么系统标题栏的双击在 Wayland 上不起作用？

**研究发现**:

**层次结构**:
```
应用程序 (egui)
    ↓
egui-winit (Rust 绑定)
    ↓
winit (跨平台抽象)
    ↓
Wayland 协议
    ↓
合成器 (GNOME Shell, KWin, etc.)
```

**关键发现**:
- 系统标题栏**不属于应用程序**
- 由**窗口管理器**渲染和管理
- Wayland 协议没有明确定义双击行为
- 依赖各个合成器的实现

#### 4.3 环境诊断

```bash
# 诊断结果
DESKTOP_SESSION: gnome
XDG_SESSION_TYPE: wayland
XDG_CURRENT_DESKTOP: GNOME

# 系统设置检查
action-double-click-titlebar: 'toggle-maximize' ✅

# 但实际测试
双击系统标题栏 → 无反应 ❌
```

**结论**: GNOME Wayland 的双击支持依赖合成器实现，winit 的支持有限

## 🎓 关键经验总结

### 1. 问题分析方法

**从现象到本质**:
```
现象: 中文显示为方块
    ↓
观察: 只在 egui 应用中出现问题
    ↓
假设: 字体问题
    ↓
验证: 检查默认字体
    ↓
根因: 默认字体不包含 CJK 字符
```

### 2. 技术选型权衡

**字体方案对比**:
| 字体 | 大小 | 授权 | 完整性 | 选择 |
|-----|------|------|--------|------|
| Noto Sans CJK | 19MB | OFL | ⭐⭐⭐⭐⭐ | ✅ |
| 文泉驿微米黑 | 4MB | GPL | ⭐⭐⭐ | 备选 |
| 站酷小薇 | 5MB | OFL | ⭐⭐⭐ | 备选 |

### 3. 平台差异认知

**Wayland vs X11**:
- X11: 成熟稳定，功能完整
- Wayland: 安全隔离，但功能有限
- **开发建议**: 两种环境都要测试

### 4. 架构理解

**egui 架构**:
```
应用层 (你的代码)
    ↓
egui (GUI 库)
    ↓
epaint (2D 图形)
    ↓
winit (窗口抽象)
    ↓
平台 API (Win32/Cocoa/X11/Wayland)
```

**关键洞察**: 跨平台抽象的代价是某些平台特性不可用
